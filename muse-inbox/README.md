# muse-inbox

Muse(巡回・チェック担当)が、読み取りやチェックの結果を置く場所です。アプリ本体(`index.html`)には、ここから自動では反映されません。Claudeが結果を読んで、確認したうえで `index.html` に反映します。

## ルール
- Museが触るのは、この `muse-inbox/` の中だけです。`index.html`・`data/`・`scripts/`・`bz-*.ics` は触りません。
- 1回のチェックにつき、新しいファイルを1つ作ります(上書きしない)。名前は `YYYY-MM-DD-内容.md`(例: `2026-11-19-unite02-setlist-check.md`)。
- 画像・PDFは置きません(リポジトリは公開のため)。テキストだけ。
- 反映済みのファイルは、Claudeが `done/` に移します。

## 書き方(1ファイル)

```
# 見出し(何をチェックしたか)
- 確認日時: 2026-11-19 10:30
- 対象: 公演名・日付・チケット・グッズなど

## 結果
- [OK] 項目 … 根拠URL
- [要修正] 項目 … 今の内容 → 正しい内容 … 根拠URL
- [新規] 項目 … 内容(日時・場所・受付期間など) … 根拠URL
- [未確定] 項目 … 読み切れなかった点・確認できなかった理由
```

- 根拠は、公式サイト・主催側・1000wave.net など、見た場所のURLを必ず付けます。
- 確認できなかったことは、確認できたことと分けて「未確定」に書きます。推測で埋めません。
- セットリストの曲順は、1000wave.net を第一の根拠にします。
